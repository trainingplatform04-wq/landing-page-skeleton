# Privacy audit, October 2026

**⚖️ Privacy Officer** · 2026-10-14 · branch `feat/gtm-consent` (base: `develop` with the article page)

What a visitor's browser sends to whom, checked in the code (read only), before Google Tag Manager is added. Each finding has its risk, what the privacy text must say, and the code change it needs, if any. This is not legal advice: each client has the privacy text checked before production (`docs/legal/go-live-checklist.md`).

Scope: the web app (`nuxt.config.ts`, `app.config.ts`, `assets/css/main.css`, `components/`, `composables/`, the installed module versions in `node_modules`). The Studio is used by editors only and is out of scope for the visitor's privacy text. ## 1. Fonts

**Finding.** No `font-family` is declared anywhere (`assets/css/main.css` imports only Tailwind and Nuxt UI; `app.config.ts` sets colours only), and Nuxt UI 4.11 declares no font of its own. The site uses Tailwind's system font stack (`ui-sans-serif, system-ui, …`): the browser loads no font file at all. Nuxt UI installs `@nuxt/fonts` 0.14; it resolves a named family **at build time** and serves the files from our own domain (`/_fonts/`), never from `fonts.googleapis.com` or `fonts.gstatic.com` at runtime. No reference to either host exists in the code.

**Risk.** None today. The LG München I judgment of 20 January 2022 (3 O 17493/20) concerns fonts fetched from Google at runtime, which does not happen.

**Privacy text.** Nothing to say. When a web font is added, the Privacy Officer checks that the built CSS contains no `fonts.googleapis.com` or `fonts.gstatic.com` URL.

## 2. Icons

**Finding.** All icons are Lucide (`i-lucide-*`), and `@iconify-json/lucide` is installed, so `@nuxt/icon` 2.5 serves them from our bundle and our own endpoint. Its default `fallbackToApi: true`, however, lets the browser ask `https://api.iconify.design` for an icon the bundle does not contain (a typo, or a new collection that is not installed). That request would send the visitor's IP address to a third party without any notice.

**Risk.** Low (does not happen with the current icons), but silent.

**Privacy text.** Nothing, once fixed.

**Required change.** `nuxt.config.ts`: `icon: { fallbackToApi: false }`. A missing icon then shows nothing instead of calling Iconify.

## 3. Colour mode

> **Update (2026-10-17):** the owner chose a dark-mode switch in the header. The preference is now the first-party cookie `color-mode` (declared necessary in the inventory, `CONSENT_REVISION` 2), so the server renders the right scheme; it holds `system` from the first visit. The lawyer check is an item of `docs/legal/go-live-checklist.md`.

**Finding.** Nuxt UI enables `@nuxtjs/color-mode`. Its client plugin writes the preference to `localStorage` (`nuxt-color-mode`, value `system`) with `immediate: true`, so on **every first visit**, although the site has no colour switch and the visitor chose nothing.

**Risk.** Medium. §25(1) TDDDG covers any storage on the visitor's device, not only cookies. A value the visitor never chose is not strictly necessary for a service they asked for (§25(2) no. 2), and it is not in the cookie inventory.

**Privacy text.** Nothing, once fixed. If it stays, it must be in the inventory (necessary, this site, until deleted) and in the table.

**Required change.** `nuxt.config.ts`: `ui: { colorMode: false }` (the site has no colour switch; this also fixes the design to the light theme the approved designs use). Alternatively, keep it and declare `nuxt-color-mode` in `constants/cookies.constants.ts` as necessary, with a rationale; the first is cleaner.

## 4. YouTube

**Finding.** `components/ArticleText/ArticleText.vue` renders a placeholder with a notice ("Playing sends data to YouTube.") and a "Load video" button; only the click makes `components/ArticleEnhancer/ArticleEnhancer.vue` insert an iframe from `www.youtube-nocookie.com` (`referrerPolicy: strict-origin-when-cross-origin`). No thumbnail is loaded from `i.ytimg.com` before the click. Without JavaScript the button is a plain link to `youtube.com`.

After loading, the player contacts several Google hosts (`youtube-nocookie.com`, `googlevideo.com`, `ytimg.com`, `google.com`) and, in "privacy-enhanced mode", still writes `localStorage` and IndexedDB entries (`yt-remote-*`, `ytidb::*`) right away and cookies such as `VISITOR_INFO1_LIVE` and `YSC` once the video plays.

**Risk.** Low with click-to-load: the click after the notice is consent for that one video. With the new **External media** category, videos load directly once it is granted.

**Privacy text.** Provider Google Ireland Limited; what is transmitted (IP address, device and browser data, the page); that nothing loads before the click or the consent; legal basis Art. 6(1)(a) GDPR and §25(1) TDDDG; possible transfer to Google LLC in the USA under the EU–US Data Privacy Framework.

**Required change.** In the inventory texts (`i18n/locales/*.json`, `cookies.youtubeVisitor` / `cookies.youtubeSession`, or one more inventory row): mention that YouTube also stores `localStorage` entries (`yt-remote-*`, `ytidb::*`) when the player loads. Recommended, not required: link the placeholder notice to the privacy page.

## 5. Contact form

**Finding.** `composables/useContactForm/useContactForm.ts` posts `name`, `email` and `message` with `$fetch` from the **browser** to `NUXT_PUBLIC_CONTACT_FORM_ACTION` (empty: the contact page shows an email link and nothing is sent). The honeypot field is not sent. The form service is chosen per client from EU-hosted services (`.env.example` lists PostTo, Formward, Forminit, Formhook, SimplyForms) and emails the owner. The form has a required checkbox linking to the privacy page. The CSP's `form-action 'self'` is unaffected (no native form post).

**Risk.** Low, if the service is in the EU and a data processing agreement (Art. 28 GDPR) is signed. The visitor's IP address reaches the service only when they send the form.

**Privacy text.** The **named** form service (company, address, country), the data (name, email, message, IP address, time), the purpose (answering the request), the legal basis (Art. 6(1)(b) GDPR for requests about a contract, otherwise Art. 6(1)(f), our interest in answering), the retention (deleted when the request is settled, unless statutory retention applies), and that writing by email is the alternative.

**Required change.** None in code. Per client: the form service's name goes into the privacy text and the go-live checklist.

## 6. Hosting (Vercel)

**Finding.** The site and its images are served by **Vercel Inc.** (440 N Barranca Ave #4133, Covina, CA 91723, USA) from its edge network. Images from Sanity go through Vercel Image Optimization (`/_vercel/image` on our domain; `nuxt.config.ts` `image.provider`), so the browser does not contact `cdn.sanity.io`. Vercel processes every request (IP address, time, URL, referrer, user agent) and keeps request and runtime logs for a short time depending on the plan. No Vercel Web Analytics or Speed Insights is installed. On **Preview** deployments (staging) Vercel injects its toolbar (`vercel.live`) for team members; production is not affected.

**Risk.** Low. Vercel is a processor (DPA available in the Vercel dashboard) and is certified under the EU–US Data Privacy Framework; the client should check the certification at dataprivacyframework.gov before go-live.

**Privacy text.** Hosting by Vercel Inc., USA; the server log data; purpose (secure delivery, error analysis); legal basis Art. 6(1)(f) GDPR; data processing agreement; transfer to the USA under the EU–US Data Privacy Framework (and the DPA's standard contractual clauses).

**Required change.** None in code. Recommended dashboard setting: switch the Vercel Toolbar off for Preview (project → Settings → General → Vercel Toolbar) when staging is shown to clients.

## 7. CMS (Sanity)

**Finding.** Content is read from Sanity (`@nuxtjs/sanity`, `useCdn: true`, no token). The first page is rendered on the server; on client-side navigation `useAsyncData` runs in the browser and calls `https://<projectId>.apicdn.sanity.io` directly, which sends the visitor's IP address and user agent to Sanity. Images do not (section 6). `og:image` and schema.org may name `cdn.sanity.io` URLs; only crawlers and social networks fetch those.

**Risk.** Low. Sanity is a processor (DPA in Sanity's terms); its infrastructure and sub-processors are partly in the USA.

**Privacy text.** Content management by Sanity (Sanity AS, Norway, with Sanity Inc., USA); the browser loads page content from Sanity's servers when moving between pages, which transmits the IP address and browser data; legal basis Art. 6(1)(f) GDPR (fast, maintainable site); data processing agreement; transfer to the USA under the EU–US Data Privacy Framework or standard contractual clauses (the client checks which applies).

**Required change.** None.

## 8. Other third-party requests

**Finding.** No other host: no `<link rel="preconnect">`, no external script, no maps, no social widgets, no `localStorage` or cookie of our own (search over `components/`, `composables/`, `layouts/`, `pages/`, `plugins/`, `utils/`). Footer social links (Instagram, YouTube) are plain links: nothing loads until clicked.

**Privacy text.** Social links: a sentence that they are plain links and nothing is sent before a click.

## Required changes

1. `nuxt.config.ts`: `ui: { colorMode: false }`, so nothing is written to `localStorage` without consent (or declare `nuxt-color-mode` as necessary in the inventory, with a rationale).
2. `nuxt.config.ts`: `icon: { fallbackToApi: false }`, so the browser never calls `api.iconify.design`.
3. Cookie inventory texts: the YouTube entries also mention the `localStorage` / IndexedDB entries the player writes (`yt-remote-*`, `ytidb::*`).

With Google Tag Manager added (`feat/gtm-consent`), the same checks apply to it: nothing from `googletagmanager.com` or `google-analytics.com` before **Statistics** is granted, ads signals always denied, `_ga` cookies deleted on withdrawal.
